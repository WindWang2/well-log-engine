# WellLogEngine 需求规格

## 1. 目的

本文定义新一代测井渲染 SDK 的产品边界、功能需求、非功能约束和验收口径。它不是对现有 ECharts/QPainter 代码的增量说明，而是新 C++20 子项目的实现依据。

## 2. 背景与问题

现有项目已经具备 LAS 解析、QPainter 曲线、岩性图纹、多井对比和 Python 原生算法扩展，但其状态、布局、数据模型和渲染职责分散在 Python Widget、Web/ECharts 与 pybind11 扩展之间。该路径难以稳定覆盖：

- 数千米深度和单曲线数十万点；
- 20 口井、100 个可见图道和一亿总样点；
- 多图道同步滚动与多井层位拉平；
- 复杂岩性图纹、曲线交会填色和专业打印；
- 图形与表格联动、原始数据复制和可审计编辑；
- PySide6 嵌入时的生命周期、线程和 GPU Context 管理。

## 3. 目标

### 3.1 产品目标

- 提供独立、可嵌入、可测试的 C++20 测井渲染 SDK。
- 在参考工作站上满足 4K、多井、一亿点场景的 60 FPS 稳态交互目标。
- 支持单井分析、多井地层对比、非线性深度对齐和跨井解释覆盖层。
- 以同一场景语义驱动 OpenGL 屏幕显示与 PDF/SVG 输出。
- 通过原生 Qt Widget 无缝嵌入 C++ Qt 和 Python PySide6 项目。
- 提供虚拟化表格、图表联动选择、复制和结构化数据导出。
- 保持原始曲线不可变，并为解释修改、QC 与派生曲线提供可审计路径。

### 3.2 工程目标

- 核心公共 API 不暴露 Qt、Python、Arrow 或 OpenGL 对象。
- 所有大数组可以零拷贝接入，并具有明确生命周期。
- 渲染状态只有一个事实来源，不在 Python、Qt Widget 和核心间镜像同步。
- 所有外部资产按不可信输入验证。
- API、Manifest 和发布包具有明确兼容策略。

## 4. 非目标

- 首期不替代 LAS、DLIS、LIS、716、WITSML 等完整数据生态；解析器属于 `welllog-io`。
- 首期不提供 QML、macOS、ARM、移动端和嵌入式支持。
- 首期不提供第三方原始 GL 插件或跨编译器 C++ 插件 ABI。
- 首期不提供 QPainter 软件交互渲染回退。
- 渲染内核不负责项目权限、文件管理、业务审批或数据库连接。
- 表格视图不允许直接破坏原始曲线值。
- XLSX、XML、CSV、PDF 等导出格式不作为无损项目回读格式。

## 5. 主要用户场景

### S1：单井快速浏览

用户加载一口包含数百条曲线、区间和岩性数据的井，平移、缩放、切换图道、叠加曲线并查看原始样点。首个可交互画面在已规范化数据可访问后 2 秒内出现。

### S2：多井地层对比

用户在同一画布中排列多口井，选择 MD、TVD 或 TVDSS，并按一个或多个 Marker 对齐。跨井连接带、层位线、选择和整体导出共享同一坐标与帧。

### S3：专业曲线道

用户将 GR、RT、NPHI、RHOB 等曲线合并到一个 Track。每条曲线绑定明确 Scale；NPHI–RHOB 等曲线可以在映射后的图道坐标中产生交会填色。

### S4：岩性与解释成果

用户显示地层、层序、体系域、岩性、沉积相、文本和符号。图纹在滚动中不漂移，屏幕、图例和 PDF/SVG 使用同一 Pattern Definition。

### S5：图表与表格联动

用户在图上框选深度范围，表格定位到原始样点；在表格中选择后图上高亮。复制结果包含列名、单位、Reference Depth 和 Null 语义。

### S6：非破坏编辑

用户调整层位、区间、注释、图道布局和 Depth Transform 控制点并撤销/重做。异常样点通过 QC Mask 标记，滤波或重采样产生 Derived Curve。

### S7：出版级导出

用户指定 `1:N` Document Scale、页面、深度范围和分页策略，导出 PDF/SVG 或高分辨率 PNG/TIFF。用户可明确选择纯矢量或混合高保真。

### S8：Python Qt 嵌入

PySide6 宿主把原生 `WellLogView` 加入现有布局，以 NumPy/Arrow 提交数据，通过 Qt 信号接收语义事件，并在不参与逐帧绘制的情况下驱动会话。

## 6. 功能需求

### 6.1 文档与数据

| ID | 需求 |
|---|---|
| DOC-01 | 一份 `WellLogDocument` 严格表示一口井。 |
| DOC-02 | 一个 Session 支持一份或多份文档。 |
| DOC-03 | 曲线数组只读且可共享，Buffer View 必须携带生命周期令牌。 |
| DOC-04 | Sampling Axis 支持单调递增或递减并保留重复坐标。 |
| DOC-05 | Null Bitmap 为缺测事实来源；NaN/Infinity 同样不可绘制。 |
| DOC-06 | 原始、派生曲线、QC Mask、区间、Marker 和注释具有稳定 Entity ID。 |
| DOC-07 | 支持原子 Append Batch，旧块不复制。 |
| DOC-08 | 无效单对象可跳过并诊断，结构性错误拒绝整个文档。 |

### 6.2 场景、图道与图层

| ID | 需求 |
|---|---|
| SCN-01 | Track 是布局容器，不是 QWidget 或业务数据类型。 |
| SCN-02 | 内置 Layer 至少覆盖网格、曲线、区间、填充、图纹、图像、文本和符号。 |
| SCN-03 | 多曲线可共享或分别绑定 Track Scale。 |
| SCN-04 | Scale 支持线性、对数、反向、裁切范围和单位。 |
| SCN-05 | Cross-Well Overlay 不隶属单井 Track。 |
| SCN-06 | Custom Layer 使用声明式原语，不能提交 Shader 或 GL 命令。 |
| SCN-07 | 图道顺序、宽度、可见性、分组和样式可交互修改。 |

### 6.3 坐标与交互

| ID | 需求 |
|---|---|
| VIEW-01 | 明确区分源采样轴、Reference Depth、Display Depth、视口和屏幕坐标。 |
| VIEW-02 | Reference Depth 支持 MD、TVD、TVDSS。 |
| VIEW-03 | Depth Transform 单调、可逆，可表达平移和分段线性拉伸。 |
| VIEW-04 | CPU 逻辑坐标使用 `double`，GPU 使用视口中心相对 `float`。 |
| VIEW-05 | Session 单一拥有布局、视口、选择、活动工具和撤销状态。 |
| VIEW-06 | 宿主通过 View Command 和 View Event 交互。 |
| VIEW-07 | 拾取返回稳定身份、真实深度、显示深度和原始值。 |
| VIEW-08 | 图形与表格共享 Selection Set。 |

### 6.4 表格

| ID | 需求 |
|---|---|
| TBL-01 | 同 Sampling Axis 曲线形成宽表。 |
| TBL-02 | 异 Sampling Axis 曲线默认分表，不隐式插值。 |
| TBL-03 | 重采样必须由用户明确指定目标轴与方法并标为派生表。 |
| TBL-04 | Qt 表格采用虚拟化模型，不复制全部行。 |
| TBL-05 | 复制同时提供 TSV 与 HTML Table。 |
| TBL-06 | 支持完整表与 Selection Set 的 XLSX、XML、CSV 导出。 |

### 6.5 编辑

| ID | 需求 |
|---|---|
| EDT-01 | 布局、Scale、样式、层位、区间、注释、跨井连接和变换控制点支持撤销/重做。 |
| EDT-02 | 原始曲线不得原地编辑或删除样点。 |
| EDT-03 | 异常点用 QC Mask 表达。 |
| EDT-04 | 滤波、平滑、换算和重采样产生 Derived Curve，并记录来源与参数。 |
| EDT-05 | 编辑形成相对于基础 Revision 的 Document Patch。 |
| EDT-06 | 版本冲突必须显式报告，不能按名称猜测合并。 |

### 6.6 导出

| ID | 需求 |
|---|---|
| EXP-01 | 支持 PDF、SVG、PNG、TIFF。 |
| EXP-02 | PDF/SVG 支持物理页面、Document Scale、页边距和深度分页。 |
| EXP-03 | 屏幕与导出共享 Prepared Scene 和文字布局。 |
| EXP-04 | 曲线按目标页面精度生成包络矢量。 |
| EXP-05 | 图纹、区间、网格、曲线保持矢量；源图像保持栅格。 |
| EXP-06 | 纯矢量与混合模式由用户显式选择，不能静默降级。 |
| EXP-07 | 文字优先嵌入字体子集，不允许时转轮廓。 |

### 6.7 集成与诊断

| ID | 需求 |
|---|---|
| INT-01 | 提供原生 `QOpenGLWidget` 适配。 |
| INT-02 | 通过 Shiboken6 提供 PySide6 Widget 绑定。 |
| INT-03 | NumPy 与 Arrow 可零拷贝接入且生命周期安全。 |
| INT-04 | Python 不参与逐帧绘制和逐鼠标 Hover 回调。 |
| INT-05 | OpenGL 不可用时表格与 CPU 矢量导出仍可用。 |
| OBS-01 | 提供 Capability Report、Diagnostic Stream、聚合性能统计、Profiler Overlay 和 Trace。 |

## 7. 性能验收基线

参考环境：

- 8 核 x64 CPU；
- 32 GB RAM；
- Intel Iris Xe 同级或更高 GPU；
- 3840×2160 物理像素；
- Windows 10/11 x64 或正式支持的 Linux x64。

参考场景：

- 20 口井；
- 100 个可见 Track；
- 200 条曲线；
- 单曲线最多 500,000 点；
- 总计最多 100,000,000 个标量采样；
- 最多 100,000 个区间、Marker、注释及跨井对象。

| 指标 | 门槛 |
|---|---|
| 稳态交互帧时 P95 | ≤ 16.7 ms |
| 稳态交互帧时 P99 | ≤ 33.3 ms |
| 拾取延迟 P95 | ≤ 16 ms |
| GUI 线程单次阻塞 | ≤ 8 ms |
| 已规范化数据首个可交互画面 | ≤ 2 s |
| 引擎新增内存峰值 | ≤ 原始曲线缓冲区的 50% |
| GPU 原始数据策略 | 禁止全量复制全部原始曲线 |

性能要求只在固定参考硬件上形成发布门禁；共享云 CI 只检查相对微基准和功能正确性。

## 8. 可用性与正确性约束

- 缺测区不得跨越连接曲线或填充。
- 对数 Scale 的非正值不得参与绘制。
- 拉平后的 Display Depth 不得冒充真实测量值。
- Pattern 在相邻区间和滚动过程中保持相位连续。
- 选择、提示、复制和导出不得返回 LOD 伪样点。
- 同名井、同名曲线和同深度对象仍必须保持独立身份。
- Context 重建、Widget 重挂载和 Python GC 不得造成悬空引用或宿主崩溃。

## 9. 迁移验收

旧路径的迁移不是按类名逐一复刻，而是按用户能力验收：

- 单井曲线、区间、岩性、表头和缩放；
- 多曲线合并与交会填色；
- 多井对比、井距、层位拉平和连接；
- 图表选择、表格复制和导出；
- PNG/SVG/PDF 视觉与语义对等；
- Legacy 页面在同一输入上的关键数值与新引擎一致。

只有新路径达到本规范的功能、正确性和性能门槛后，才能提出删除 Legacy 实现的独立变更。
